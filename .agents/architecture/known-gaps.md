# Écarts connus entre la cible et l'implémenté

À ne pas « corriger » sans demande. La liste détaillée et datée est dans `NOTES_SANDBOX.md` et dans `docs/security/known-limitations.md` ; ce fichier en garde l'essentiel.

transport HTTP/JSON au lieu de gRPC (décidé, ADR-0050 : pas de code généré, pas de flux, `contract_test.go` vérifie les noms, pas les types) ; pas de Workflow/Approval Engine (seulement l'approbation à un décideur du break-glass, ADR-0011, dans le Broker) ni de MFA natif ; notification du break-glass sans nouvelle tentative, un seul canal (signée si `BREAKGLASS_NOTIFY_SECRET`, ADR-0013) ; alertes de l'audit poussées par webhook signé avec renvois, file dans `alert_outbox` avec une base, en mémoire sans (ADR-0045, ADR-0057) ; `GET /sessions` ne sert que `pending_approval` ; un seul protocole (SSH) ; KEK locale (`LocalKMS`) sauf si Transit est configuré (ADR-0049 : clé dans OpenBao, jeton en fichier non renouvelé, pas d'AppRole) ; Vault chiffre en un seul niveau (pas d'enveloppe) ; lignes du recorder non chaînées ; événements d'audit attribués à l'identité du certificat de l'émetteur depuis ADR-0027 (`emitter`), sans liste d'actions permises par émetteur ; listes d'appelants dans le code ; la limite par adresse du Gateway ne vaut que si `TRUSTED_PROXY_CIDRS` est réglé (ADR-0015 ; Traefik n'a pas été essayé) et ne borne pas une force brute distribuée ; seuls `POST /sessions`, `approve`, `reject`, `connect` et `terminate` ont un budget par identité (les lectures n'en ont pas) ; `terminate` a un contrôle (ADR-0017) et coupe (ADR-0018) le proxy SSH peut avoir plusieurs instances, connues du Broker (`SSH_PROXY_URLS`, ADR-0046 : ticket chez une, révocation chez toutes ; **une instance injoignable empêche toute terminaison** ; pas d'équilibreur devant les ports SSH), les octrois de portée du Vault ne sont pas révoqués, le mode est strict (proxy injoignable ⇒ on ne peut pas terminer), et un refus de lecture d'une session (`GET /sessions/{id}`) est audité **dans une limite par identité** (ADR-0020), le nombre exact de refus supprimés n'est pas enregistré, la lecture servie à un titulaire de politique est un événement avant d'être servie (ADR-0021) — **ne pas la passer par `refusalbudget.Budget`, ni l'écrire après ou en arrière-plan** —, une panne de l'audit rend donc la lecture d'un auditeur indisponible (voulu), le demandeur et le décideur ne sont pas tracés, chaque page d'un enregistrement du Command Recorder servie est un événement `recording.read` écrit avant d'être servie (ADR-0022) — **même règle : pas de budget, pas d'écriture après ou en arrière-plan** — un refus de lecture d'un enregistrement est audité dans un budget par identité (ADR-0024, `pkg/refusalbudget` partagé avec le Broker) ; chaque demande servie par la liste des demandes en attente est un événement `session.listed` écrit avant d'être servie (ADR-0023, même règle) ; et chaque refus interroge toujours l'Authorization Service ; budgets par processus ; refus par adresse ni audités ni journalisés.
