# Invariants — ne les affaiblis jamais

Chaque ligne est tenue par du code et par des tests. Si une tâche semble exiger d'en affaiblir une, **arrête-toi et demande** (`policies/security.md`). Ce tableau a priorité sur `rules/` et `settings/` (ordre de priorité : `AGENTS.md`).

| ID | Invariant | Où il est tenu |
|---|---|---|
| ADR-0003 | Un secret ne traverse jamais le control plane (Gateway, Broker). Seul le proxy échange un scope à usage unique contre un credential, directement auprès du Vault. | Le port `VaultAuthorizer` du Broker n'a **aucune méthode** pour lire un credential ; `pkg/proxycore` purge le secret octet par octet. |
| ADR-0008 | Une session qui ne peut pas être enregistrée n'a pas lieu ; une commande non acquittée par le recorder n'est jamais exécutée. | `RECORDING_POLICY=required` par défaut (`pkg/proxycore`, ssh-proxy). |
| ADR-0009 | Le break-glass ne retire que l'enregistrement acquitté, sous six verrous cumulés, et jamais en silence. | Broker + `proxycore.Admission` (preuve à champs non exportés). |
| ADR-0011 | Une demande break-glass n'ouvre rien tant qu'une **autre** personne ne l'a pas approuvée : pas d'auto-approbation (par identifiant d'utilisateur), décideur et rôles tirés du jeton vérifié par la Gateway, décision auditée avant d'agir puis compare-and-swap, `connect` réservé au demandeur. | Session Broker (`decide`, `SaveIfStatus`) + liste blanche des routes `/sessions/...` du Gateway. |
| ADR-0012 | La liste des demandes break-glass en attente ne montre que ce que l'appelant peut décider (vide, jamais 403, sans autorité ; 503 plutôt qu'une liste partielle) ; la notification est au mieux et **n'est jamais un contrôle** (port sans valeur de retour, asynchrone, après coup) ; l'URL du webhook est un secret (jamais journalisée) ; ce que le demandeur écrit (`targetAccountId`) n'atteint jamais tel quel un message lu par des tiers. | Session Broker (`ListPendingApprovals`, `ApprovalNotifier`, `infrastructure/webhook_notifier.go`, `wellFormedAccountID`) + Gateway (`handleListPending` reconstruit la requête). |
| ADR-0013 | Un demandeur ne peut pas avoir plus de `BREAKGLASS_MAX_PENDING_PER_REQUESTER` demandes en attente (3 par défaut ; **par demandeur**, jamais global ni par compte : un plafond partagé serait une arme) ; le plafond est tenu **atomiquement**, entre réplicas aussi ; un décompte impossible est un 503, jamais une acceptation ; il n'est demandé qu'après l'autorité ; le webhook, si `BREAKGLASS_NOTIFY_SECRET` est fixé, est signé (`v1=` HMAC-SHA256 de `horodatage.corps`) et le secret n'apparaît jamais dans un journal ni une erreur. | Session Broker (`checkPendingQuota`, `SaveIfUnderPendingLimit` dans les deux magasins — verrou consultatif PostgreSQL —, `WebhookNotifier.WithSecret`) + relais du `429` par le Gateway. |
| ADR-0014 | Le budget de `POST /sessions` est celui de l'**utilisateur vérifié** (`id.UserID` issu du jeton), jamais de l'adresse ni du corps ; chaque tentative le coûte **avant** la lecture du corps, et une demande refusée par lui n'atteint pas le Broker (ni ligne, ni événement d'audit) ; défauts stricts (rafale 10, 6 par minute), pas d'« illimité » ; `429` avec un `Retry-After` vrai, message distinct du plafond du Broker ; un refus laisse une ligne de journal par utilisateur et par épisode — pas d'audit (le Gateway n'est pas émetteur autorisé, ADR-0010) ; l'éviction des seaux inactifs ne change jamais une décision. | API Gateway (`admitSessionRequest`, `application.RateLimiter.Take`/`Decision`, `NewSessionRequestLimiter`, `sweep`). |
| ADR-0015 | L'adresse du client des limites par adresse n'est **jamais** choisie par le client : `X-Forwarded-For` n'est lu que si le pair TCP immédiat est dans `TRUSTED_PROXY_CIDRS` (défaut : personne), **de droite à gauche**, jusqu'à la première adresse qui n'est pas un proxy ; au moindre doute la clé est l'adresse du **pair** ; clés normalisées (IPv4 écrite en IPv6 → IPv4, IPv6 → /64) ; une confiance plus large que prévue (réseau de longueur 0 sous toutes ses écritures, bits d'hôte, entrée vide) empêche de démarrer ; les limites par adresse sont réglables (`CLIENT_LOGIN_*`, `CLIENT_REQUEST_*`), défauts = ce que le code faisait, jamais « illimité ». | API Gateway (`application.ProxyTrust.ClientKey` — fonction pure —, `ParseTrustedProxies`, `addressKey`, `GatewayServer.clientKey`, `WithProxyTrust`). |
| ADR-0016 | Les routes qui **écrivent à chaque appel** — `approve`, `reject`, `connect`, et `terminate` depuis ADR-0017 — ont un budget par **utilisateur vérifié** (`id.UserID`, jamais l'adresse ni le corps), **un seul seau pour les quatre**, distinct de celui de `POST /sessions` ; le jeton est pris **avant** que le Broker soit appelé (une action refusée n'atteint ni le Broker, ni le Vault, ni le proxy, et n'écrit aucun événement) et après la vérification de la méthode (`405` gratuit) ; les lectures ne sont **pas** comptées (pas d'écriture à chaque appel) ; `SESSION_ACTION_BURST` (défaut 10, 1 à 1000) et `SESSION_ACTION_RATE_PER_MINUTE` (défaut 6, 1 à 600), jamais « illimité ». Ajouter une route qui écrit à chaque appel = l'ajouter ici, avec son cas de test. | API Gateway (`GatewayServer.admitSessionAction`, `admitFromBudget`, `WithSessionActionLimiter`, `application.NewSessionActionLimiter`). |
| ADR-0017 | Mettre fin à une session : **son demandeur** (sans politique) **ou** une politique sur `session-terminate:account:{id}` (refusée par défaut, préfixe distinct de `vault:`, `breakglass:` et `breakglass-approve:`) ; l'appelant et ses rôles viennent du **jeton vérifié** (le Gateway construit `{callerId, actorRoles}`, le corps du client est écarté, sans `callerId` : `403`) ; ordre **session (404) → appelant (403, quel que soit l'état) → état (409)**, Authorization injoignable : `503` et rien n'est terminé ; l'audit nomme **l'appelant** (refus : `session.terminate` en échec sous son nom ; succès après l'action, au mieux ; `404`/`409` sans événement) ; terminaison par comparaison-échange (`SaveIfStatus` depuis `active`) ; la route est dans le budget d'actions d'ADR-0016, avant le Broker. **Ne coupe pas une connexion déjà ouverte** (le proxy n'a pas de route de révocation). | Session Broker (`TerminateSession`, `SessionTerminateResourcePrefix`, `handleTerminate`) + Gateway (`handleSessionItem`, cas `DELETE`). |
| ADR-0018 | **Terminer, c'est couper** : `TerminateSession` fait révoquer la session au proxy (`POST /internal/v1/revoke-session`, **Broker seul**, ADR-0010) **avant** de changer l'enregistrement (`SaveIfStatus`) ; `200` seulement quand plus rien n'est ouvert, sinon `503` : **rien n'est terminé**, la session reste `active`, `session.terminate` en échec sous le nom de l'appelant, le même appel rejoué aboutit ; jamais d'appel au proxy pour une terminaison refusée / session inconnue / non active / expirée / Authorization muette. Le proxy tient `proxycore.LiveSessions` (connexions + mémoire des révocations, **un seul verrou**) partagé avec `Listener.Serve` (qui enregistre **avant** l'admission, l'audit et le credential ; `relayCtx` dérive de `liveCtx`) ; il jette les tickets non utilisés, refuse `establish-session` (`409`) pour une session révoquée avant d'interroger l'enregistreur, ferme la connexion cible à l'annulation (`context.AfterFunc`, y compris pendant la poignée de main). Mémoire = temps restant + 1 min, plafond 7 jours, comparée **en secondes** avant conversion. Audit proxy : `session.revoked` + `session.terminate` ; un arrêt du proxy n'est pas une révocation ; l'opérateur lit « session ended because it was terminated. » sans savoir qui. Un `Listener`/serveur sans registre refuse toute session (`ErrNotRevocable`). `conn.RelayEnded()` juste après le relais, avant l'audit. |
| ADR-0019 | Lire une session : **son demandeur** (sans politique), **celui qui l'a décidée** (`DecidedBy` = appelant, cette session seulement) **ou** une politique sur `session-read:account:{id}` (action `session:read`, refusée par défaut, préfixe distinct de `vault:`, `breakglass:`, `breakglass-approve:`, `session-terminate:`) ; le Gateway construit `?callerId=&actorRoles=` d'après le **jeton vérifié** (`forwardRead` : la requête et le corps du client sont écartés, rôles encodés) ; ordre appelant vide `403` → session `404` → appelant `403` → Authorization `503` (échec fermé, tiers seulement) ; le refus est **générique** (jamais la raison de l'Authorization Service) ; une erreur du store qui n'est pas `ErrNotFound` est un `503`, jamais un `404` ; **une lecture n'écrit jamais dans le store** et reste hors du budget d'actions ; à l'audit, seul le refus de politique (ADR-0020) et la lecture servie à un titulaire de politique (ADR-0021) écrivent — le demandeur et le décideur n'écrivent rien. | Session Broker (`GetSession`, `handleGetSession`) + Gateway (`forwardRead`) + règle mTLS `/sessions/`. |
| ADR-0020 | **Un refus de politique d'une lecture** (`403` d'un appelant nommé, session existante) écrit `session.read`, `resource_type=session`, `success=false`, **sous le nom de l'appelant que le Gateway a vérifié** (jamais `sess.RequestedBy`, jamais une valeur de la requête), **dans la limite d'un budget par identité** (`refusalbudget.Budget`, seau à jetons de `pkg/refusalbudget` — dans le Broker jusqu'à ADR-0024 —, par identité et pas par session) : `SESSION_READ_AUDIT_BURST` (10, de 1 à 1000) puis `SESSION_READ_AUDIT_RATE_PER_MINUTE` (6, de 1 à 600), invalide ⇒ le Broker s'arrête, ni « illimité » ni « désactivé » ; **la réponse ne dépend jamais du budget** (refus identique, écrit ou non ; audit en panne ⇒ même refus, cause dans le journal ; ce n'est pas « enregistrer ou refuser ») ; une ligne de journal **par épisode** quand le budget est épuisé ; `404`, `503`, appelant vide et lecture servie n'écrivent rien ; mémoire bornée (seau revenu plein oublié), horloge qui recule sans effet ; par processus (N répliques ⇒ N×). | Session Broker (`auditRefusedRead`, `refusal_budget.go`, `main.go`) ; le Gateway ne change pas. |
| ADR-0021 | **Une lecture servie à un titulaire de politique** (le chemin `allowed` de `GetSession`, ni le demandeur ni le décideur) écrit `session.read`, `resource_type=session`, **`success=true`**, sous le nom de l'appelant que le Gateway a vérifié, **avant** de servir ; **si l'événement ne s'écrit pas, rien n'est servi** : `ErrUnavailable` (`503`), ni `ErrForbidden` ni `ErrNotFound`, la cause dans l'erreur pour le journal du gestionnaire, jamais au client ; **pas de budget** (celui d'ADR-0020 borne les refus ; une lecture servie n'en dépense aucun jeton et n'est pas réduite au silence par lui) ; asymétrie voulue : ce qui réduit un accès (terminer, refus de lecture) est au mieux, ce qui accorde — session, approbation, **connaissance** — est fermé ; le demandeur et le décideur n'écrivent rien et ne dépendent pas de l'audit ; l'ordre est appelant vide `403` → session `404` → appelant `403` → Authorization `503` → **audit `503`** → servi. | Session Broker (`GetSession`) ; le Gateway ne change pas. |
| ADR-0022 | **Chaque page d'un enregistrement du Command Recorder servie** (`GET /sessions/{id}/recording`) écrit `recording.read`, `resource_type=session`, `resource_id`=la session, **`success=true`**, sous le nom de l'appelant que le Gateway a vérifié (`?callerId=` construit d'après le jeton, celui du client écarté), **avant** d'être servie ; **sans l'événement, rien n'est servi** : `ErrUnavailable` (`503`, corps générique, cause au journal du Recorder) ; pas d'exception demandeur (toute lecture d'un enregistrement passe par une politique), **pas de budget** ; ordre appelant vide `403` → Authorization `403` / `503` (plus `403` quand elle est muette) → store `500` (corps générique) → **audit `503`** → servi ; un refus est un événement depuis ADR-0024. `AUDIT_URL` du Recorder sans réglage pour le désactiver. | Command Recorder (`GetRecording`, `handleSession`, `AuditHTTPClient`) + Gateway (`handleSessionRecording`) + règle mTLS `emit-event` de l'Audit Service ouverte à `command-recorder`. |
| ADR-0023 | **Chaque demande de la page servie par la liste des demandes en attente** (`ListPendingApprovals`, `GET /sessions?status=pending_approval`) écrit `session.listed`, `resource_type=session`, `resource_id`=la demande, **`success=true`**, sous le nom de l'appelant que le Gateway a vérifié, **avant** de servir la page ; **un seul qui ne s'écrit pas, et rien n'est servi** (`ErrUnavailable`, `503` générique) ; seulement les demandes **de la page servie** (pas celles comptées dans `totalItems`, pas celles écartées par le filtre) ; **une page vide n'écrit rien** et ne dépend pas de l'audit ; pas de budget ; écriture séquentielle, au plus `pageSize` (100) appels. | Session Broker (`ListPendingApprovals`) ; le Gateway ne change pas. |
| ADR-0024 | **Un refus de politique d'une lecture d'enregistrement** écrit `recording.read`, `resource_type=session`, **`success=false`**, sous le nom de l'appelant vérifié, **au mieux** et **dans un budget par identité** (`pkg/refusalbudget`, le même modèle et le même code qu'ADR-0020 — déplacé du Broker, partagé ; `RECORDING_READ_AUDIT_BURST` 10 de 1 à 1000, `RECORDING_READ_AUDIT_RATE_PER_MINUTE` 6 de 1 à 600, hors bornes fatal, annoncé au démarrage) ; la réponse ne dépend ni du budget ni de l'audit ; une ligne de journal par épisode ; **un identifiant qui ne peut pas être une session** (vide, > 256 octets, pas UTF-8) est un `400` avant toute question, sans événement — aucune lecture n'écrit dans la trace une chaîne choisie par l'appelant ; une lecture servie ne dépense aucun jeton. | Command Recorder (`GetRecording`, `auditRefusedRead`, `main.go`) + `pkg/refusalbudget` (Broker et Recorder). |
| ADR-0025 | **L'Audit Service ne prend dans la trace que ce qu'un émetteur peut vouloir dire** : action 1–64 octets `[a-z0-9_.]`, `resource_type` 1–64 `[a-z0-9_]`, `resource_id` 1–256 et auteur 0–256 octets UTF-8 **sans caractère de contrôle** ; corps ≤ 16 Kio (`413`) ; `POST` seulement (`405`) ; hors bornes `400` qui nomme le champ et la règle, **jamais la valeur** ; validé **avant** de toucher la chaîne ; une erreur du store est un `500` générique, cause au journal. Un émetteur qui reçoit `400` échoue comme pour toute panne de l'audit (fermé là où il l'est). Le Recorder refuse en amont (`400`) un identifiant de session hors de ces bornes. | Audit Service (`validate`, `handleEmitEvent`) + Command Recorder (`usableSessionID`). |
| ADR-0026 | **Le hash d'un événement d'audit est au format 2** : `SHA-256("openbastion.audit.event.v2\x00" ‖ len32‖prev_hash ‖ len32‖id ‖ len32‖actor ‖ len32‖action ‖ len32‖type ‖ len32‖resource ‖ success ‖ ts_ns)` ; la version est stockée (`hash_version`, défaut 1 pour les lignes antérieures) ; **seul le format 2 s'écrit** ; `VerifyChain` vérifie chaque ligne dans son format, refuse une version inconnue (qui n'a pas de hash) et une version qui recule. **Ne jamais changer un format existant** : un nouveau format est une nouvelle version (vecteurs figés dans `canonical_hash_test.go`). | Audit Service (`computeHash`, `VerifyChain`, `PostgresStore`, `001_init.sql`). |
| ADR-0027 | **La chaîne d'audit est à clé** : format 3 = `HMAC-SHA256(clé, "openbastion.audit.event.v3\x00" ‖ L(prev) ‖ L(id) ‖ L(actor) ‖ L(action) ‖ L(type) ‖ L(resource) ‖ L(emitter) ‖ L(key_id) ‖ success ‖ ts_ns)`, seul format écrit ; **`AUDIT_CHAIN_KEY_HEX` obligatoire avec `DATABASE_URL`** (fatal sans, jamais affichée ni journalisée), aléatoire en mémoire ; `AUDIT_CHAIN_PREVIOUS_KEYS_HEX` vérifie, ne signe pas ; `chain_key_id` = 8 premiers octets d'un SHA-256 étiqueté de la clé ; **`emitter` = `mtls.CallerFrom`**, jamais le corps ; une ligne v1/v2 ne porte ni émetteur ni clé ; comparaison `hmac.Equal`. | Audit Service (`chain_keys.go`, `EmitEventAs`, `VerifyChain`, `main.go`, `001_init.sql`). |
| ADR-0028 | **La tête de la chaîne est ancrée hors de la base** : `AnchorSink` (fichier JSON lines `AUDIT_ANCHOR_FILE`, absolu, 0600, **jamais recréé**, `fsync`) ; **obligatoire avec `DATABASE_URL`** ; `AUDIT_ANCHOR_INTERVAL_SECONDS` 60 (1–3600, fatal hors bornes) ; une ancre = `{event_id, hash, at, key_id, mac}`, MAC = `HMAC(clé, "openbastion.audit.anchor.v1\x00" ‖ L(event_id) ‖ L(hash) ‖ L(key_id) ‖ at_ns)` ; **l'ancre nomme `tip` (le dernier événement écrit par ce processus, avec son hash calculé), pas `store.Last`** sauf au démarrage ; `verifyAnchors` : MAC, clé tenue, événement présent, même hash, ordre ; ancres illisibles ⇒ `ErrAnchorsUnavailable` ⇒ `503`. **Audit Service en instance unique.** | Audit Service (`anchors.go`, `anchor_file.go`, `main.go` `anchorEvery`, `handleVerifyChain`). |
| ADR-0029 | **Pas d'ORM** : les magasins restent en `database/sql` et SQL écrit à la main, derrière les ports de domaine ; aucun ORM ni constructeur de requêtes (décision de Bony Kiss, option A de `docs/architecture/data-access-orm-analysis.md`). | Tous les magasins PostgreSQL. |
| ADR-0030 | **Migrations de schéma versionnées** : un fichier `migrations/NNN_nom.sql` par évolution, numéros continus (un trou ou un doublon refuse le démarrage) ; chaque migration appliquée **une fois**, en transaction, sous un verrou PostgreSQL **propre au service**, enregistrée dans `schema_migrations (component, version, name, checksum)` ; **le texte appliqué ne change plus** (un checksum différent refuse le démarrage — corriger, c'est écrire une nouvelle migration) ; une base plus récente que le binaire démarre et le dit ; pas de migration descendante. | `pkg/migrate` (bibliothèque standard + `database/sql`), les six magasins PostgreSQL. |
| ADR-0031 | **`audit_events` n'est pas partitionné** (mesuré : plus d'unicité globale de l'id, insertion hors partition = audit arrêté, 41 s/M de conversion, lecture 2,3×) ; le DDL de `docs/architecture/data-architecture.md` est une cible. | Audit Service (schéma). |
| ADR-0032 | **Rétention par point de contrôle**, désactivée par défaut (`AUDIT_ARCHIVE_DIR` absolu + `AUDIT_RETENTION_MONTHS` 1–120, l'un sans l'autre fatal, demande `AUDIT_ANCHOR_FILE`) ; au démarrage puis toutes les heures, **mois civils entiers** plus vieux que la rétention, le plus ancien d'abord : `VerifyChain` complet (échec ⇒ rien ne bouge) → archive `audit-AAAA-MM.jsonl` (temporaire, `fsync`, `link` — jamais écrasée —, relue, SHA-256) → `Checkpoint` dans le fichier d'ancres (`kind: checkpoint`, MAC `openbastion.audit.checkpoint.v1`, `PrevHash` = `LastHash` du précédent, `AnchorsCovered`) → événement `audit.archived` (émetteur `audit-service`) → `DeleteThrough` (transaction, nombre exact). `VerifyChain` repart du point de contrôle dont `LastHash` = `prev_hash` du premier événement (sinon `409` « start of the chain was cut ») ; les `AnchorsCovered` premières ancres peuvent manquer ; reprise d'un point de contrôle aux événements encore présents. Les ancres gardent leur format. | Audit Service (`archive.go`, `archive_file.go`, `anchor_file.go`, `DeleteThrough`, `main.go` `archiveEvery`). |
| ADR-0033 | **Déploiement `docker-compose`** : une image (`golang:1.23-alpine` → `distroless/static-debian12:nonroot`, 65532), **mTLS obligatoire**, conteneurs nommés comme leur identité (le certificat porte ce nom DNS) ; **autorité et sa clé dans le volume `pki-ca`, monté par le seul job `pki`** ; chaque service ne monte que **son** sous-répertoire du volume `pki` (`subpath`, lecture seule) ; une base et un rôle par service (`REVOKE … FROM PUBLIC`, identifiants entre guillemets : `authorization` est réservé) ; `SKIP_DEMO_SEED=1` partout ; seuls la Gateway et le port SSH du proxy publiés, sur `127.0.0.1` ; premiers utilisateurs par `cli user create` (mot de passe sur l'entrée standard). Le test `compose_test.go` est le critère de sortie n° 3 du MVP. | `deploy/docker-compose/`, `cli/openbastion-cli/`, `test/integration/cmd/demo-ssh-target`. |
| ADR-0034 | **Expiration écrite** : le Broker balaie (`SESSION_EXPIRY_SWEEP_SECONDS` 30, 1–3600, fatal hors bornes, sans interrupteur) ; `ExpireDue` = un `UPDATE … WHERE id IN (SELECT … FOR UPDATE SKIP LOCKED)` dans une CTE triée (une session expire une fois, quel que soit le réplica) → `session.expire` (acteur vide, ressource `session`) → `MarkExpiryAudited` ; `expiry_audited = false` tant que l'audit n'a pas accepté (au moins une fois) ; le processus réessaie les siennes au balayage suivant, les autres après `ExpiryAuditGrace` (30 s > `ExpirySweepTimeout` 10 s) ; migration `002_session_expiry.sql`. | Session Broker (`session_expiry.go`, `ExpireDue`/`ExpiriesToAudit`/`MarkExpiryAudited`, `main.go` `expireEvery`). |
| ADR-0035 | **Connexion fédérée OIDC** (désactivée par défaut ; `OIDC_ISSUER`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET`, `OIDC_REDIRECT_URL`, `OIDC_ROLE_MAP_FILE` tout ou rien, `OIDC_GROUPS_CLAIM`) : stdlib + golang-jwt, **aucune dépendance ajoutée** ; découverte (émetteur exact, `https` ou boucle locale), code + PKCE S256, `state`/`nonce` en base (`oidc_login_attempts`, `DELETE … RETURNING`, 10 min) ; jeton d'identité : RS256/ES256, l'algorithme imposé par le type de la clé, `iss`, `aud`, `azp`, `exp` exigé, `iat`, `nbf`, 60 s, `nonce`, `sub` ; clés relues au plus une fois par minute, RSA ≥ 2048 ; **rôles = table déclarée seulement**, aucun rôle ⇒ `403` sans compte créé, recalculés à chaque connexion ; compte `oidc:<sub>`, sans mot de passe. Gateway : `POST /auth/oidc/start`, `POST /auth/oidc/callback`, dans le budget de connexion (deux prises par connexion), corps reconstruit. | Authentication (`oidc.go`, `oidc_provider.go`, routes `/auth/v1/oidc/*` réservées à `api-gateway`), Gateway (`handleOIDC`). |
